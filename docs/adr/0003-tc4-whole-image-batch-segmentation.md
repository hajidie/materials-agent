# TC4 初生 α 相分割采用整图批量处理

用户确认第一版在聊天中一次上传多张模型适用的 TC4 显微组织图片，由一次工具调用提交本次图片清单，后台确定性地逐张处理，返回每张图片的分割叠加图、二值掩膜和预测面积占比。相比由 Agent 为每张图片分别决定并调用工具，这减少模型调用轮次，也要求各图片的状态、输入和成果保持明确对应。

第一版按当前样例的普通 8 位 PNG/JPG 图片范围设计，沿用已跑通的模型预处理；输入尺寸不固定为样例的 604×604，结果恢复到输入图片尺寸。用户确认整图处理，包括图片文件本身的细边框；预测面积占比的分母为输入图片全部像素。暂不加入 TIFF 兼容、底部标注区识别、自动裁边或逐图自动增强，以限定第一版范围和保持已验证的处理方式。

本机适用样图 `image_518.png` 实际采用 8 位 RGBA 编码，alpha 全为 255。因此普通图片范围兼容完全不透明的 RGBA PNG，保留原文件和身份，推理时转换为 RGB，不改变 RGB 像素值或预处理版本。含真实透明或半透明像素时拒绝，不自行选择填充背景。

用户确认单张输入问题标记失败后继续处理其余图片，并逐张汇总；Runtime 或 GPU 故障、已派发结果未知时暂停后续执行，保留已完成成果。停止、浏览器断线和恢复沿用 [ADR-0002](0002-run-independent-of-browser-connection.md)，结果未知时核查原操作，不自动重复派发。

实现通过 Managed Tool 的集合资源绑定、父 ToolRun 下的 ToolRunItem、逐张成果保存与 Runtime 原身份回执核查落实此决定。每批最多 10 张，每张最多 10 MiB，宽高分别 128–4096；这些是执行限制，不固定样例尺寸。停止检查在每张派发前执行，已派发项仍可保存迟到回执；未知结果只核查，不能自动重跑。图片项决定批量结果状态，SEM/EBSD 保留原规则。模型与预处理版本关联到每张成果，对话删除通过持久清理队列处理终态回执。

最初约定工具默认关闭。用户于 2026-10-09 进一步要求日常一键启动开启全部业务工具与功能，因此 `start-all.ps1` 默认开启 TC4 与 ML；底层按需启动和独立 Backend 的默认配置继续保留。启用时必须检查 AVAILABLE。没有人工标注时只能验证推理与原程序一致、像素统计正确及工程链路可用，不能据此报告科学准确率。部署与验证入口分别见 README、架构说明及验证指南；本次实施追踪见 [Issue #1](https://github.com/hajidie/materials-agent/issues/1)。
